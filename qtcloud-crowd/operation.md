# 量潮众包云运营策略

## 定位

qtcloud-crowd 是 qtcrowd 的管理后台：运营管理、任务管理、数据观测都在这里进行。管理任务非常碎片化——核心是把**人、财、事**管理好，把大批量碎片化任务管理好。

## 信用管理

- 众包前台依赖后台的**众包员**去提供关于人才事务的管理，**信用是其中的一部分**——信用本身对众包市场的运作非常重要
- 有招聘活动时，把信息转移到人事，通过**事件队列**之类的机制转一下即可
- 未决问题：信用数据如何跨系统流转（是否需要独立的信用子系统、租户隔离策略是什么）——目前只有两个子系统，事件队列流转足够；在数据没有彻底打通前，前台按既定规则走

## 数据观测

- 录制通过率 → 录制者信用、分解质量信号
- 审核记录覆盖/硬伤 → 视频质量信号、审核标准松紧
- 选券 vs 选现金比例 → 接单人分群情况、10 倍倍率是否合适
- 竞价压价幅度 → 指导价是否合理
- 代金券消耗 → 课程额度紧张度（额度不足时下调代金券倍率）

## 定价调节

- 指导价调节：根据竞价压价幅度调整录制/审核指导价
- 倍率调节：课程额度不足时逐步下调代金券倍率（10 倍 → 逐步下调）
- **课堂成熟度调节**：目前课程还比较依赖人上课，未来课堂成熟以后对人上课的依赖会下降，代金券比例也跟着下调——课堂越成熟，代金券的锚（课程价值）越稳固，倍率越可以收紧

## 验证路径

与课程云试水课同步：观察试水课期间的众包数据（选券比例、竞价幅度、通过率），验证定价与倍率是否合理。
