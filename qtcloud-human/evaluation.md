# 量潮招聘系统原型业务评估

## 业务背景

### 当前痛点（来自 docs/）

当前招聘流程依赖邮件作为核心通信渠道：

```
投递邮件 → 读取邮箱 → 缓存问卷链接 → 发送邮件 → 归档到文件夹
```

**具体痛点**：
1. 问卷链接需要手动从邮箱缓存
2. 候选人信息需要从邮件主题解析
3. 依赖 lark-cli 发送邮件
4. 状态靠邮件文件夹管理
5. 无法追踪候选人是否已读

### 业务目标

**让邮件从招聘流程里消失，所有流程走自研系统。**

### 核心业务流程

```
投递 → 问卷 → 审核 → 邀请 → 入群 → 考核 → 评估 → Offer
```

## 业务评估维度

### 评估维度 1：候选人投递能力

**业务需求**（来自 candidate-experience.md）：
- 候选人访问招聘页面，填写基本信息，上传简历，提交投递
- 提交后，系统自动发送通知：「感谢投递，请先完成准入问卷。」

**评估问题**：
- [ ] 候选人能否在系统内完成投递？
- [ ] 投递后系统能否自动发送问卷通知？
- [ ] 通知内容是否包含问卷链接？

**验证方法**：
1. 访问候选人门户，检查是否有投递入口
2. 提交投递，检查是否收到问卷通知
3. 检查通知内容是否包含问卷链接

---

### 评估维度 2：问卷管理能力

**业务需求**（来自 survey.md）：
- 问卷链接存储到系统，HR 可在后台管理
- 候选人信息存储到系统，不再从邮件解析
- 候选人投递后，系统自动发送站内信通知
- 通知内容包含问卷链接

**评估问题**：
- [ ] 问卷链接能否在系统内管理？（而非从邮箱缓存）
- [ ] 候选人能否在系统内看到问卷链接？
- [ ] 候选人能否在系统内填写问卷？
- [ ] 问卷提交后系统能否自动记录？

**验证方法**：
1. 检查管理工作台是否有问卷管理功能
2. 检查候选人门户是否显示问卷链接
3. 检查问卷填写流程是否完整
4. 检查问卷提交后状态是否自动更新

---

### 评估维度 3：通知能力

**业务需求**（来自 notification.md）：

候选人收到的通知：
| 时机 | 通知内容 |
|------|----------|
| 投递后 | 请填写准入问卷（附问卷链接）|
| 问卷提交后 | 问卷已收到 |
| 审核通过后 | 欢迎加入实训基地（附群二维码）|
| 进入考核后 | 你已进入考核阶段 |
| 考核通过后 | 恭喜通过考核 |

HR 收到的通知：
| 时机 | 通知内容 |
|------|----------|
| 新投递 | 有新的候选人投递 |
| 问卷提交 | 有候选人提交问卷 |
| 候选人入群 | 有候选人加入实训群 |
| 考核提交 | 有候选人提交考核 |

**评估问题**：
- [ ] 系统能否自动发送站内信通知？（替代邮件）
- [ ] 通知状态能否追踪？（已读/未读）
- [ ] HR 能否看到通知发送状态？
- [ ] 候选人能否在系统内看到所有通知？

**验证方法**：
1. 触发各种业务场景，检查是否自动发送通知
2. 检查通知中心是否显示已读/未读状态
3. 检查 HR 后台是否能看到通知发送状态

---

### 评估维度 4：审核能力

**业务需求**（来自 workflow.md）：

审核阶段：
- 进入条件：候选人提交问卷
- 系统行为：展示问卷答案给 HR，提供审核操作（通过/拒绝）
- 退出条件：HR 审核通过 → 发送邀请；HR 审核拒绝 → 通知候选人

**评估问题**：
- [ ] HR 能否在系统内看到候选人问卷答案？
- [ ] HR 能否在系统内执行审核操作（通过/拒绝）？
- [ ] 审核通过后系统能否自动发送邀请通知？
- [ ] 审核拒绝后系统能否自动通知候选人？

**验证方法**：
1. 提交问卷后，检查 HR 后台是否能看到问卷答案
2. 执行审核操作，检查是否触发后续流程
3. 检查审核结果是否自动通知候选人

---

### 评估维度 5：邀请能力

**业务需求**（来自 send-invite-email.md）：

当前流程：
- 从飞书多维表格获取问卷提交者名单
- 对比已发送邀请名单，找出未发送的
- 发送邀请邮件，附带群二维码

理想流程：
- HR 审核通过后，系统自动发送邀请通知
- 通知中包含实训基地群二维码
- 候选人扫码入群

**评估问题**：
- [ ] 群二维码能否在系统内管理？（而非手动缓存）
- [ ] 审核通过后系统能否自动发送邀请通知？
- [ ] 邀请通知是否包含群二维码？
- [ ] HR 能否批量发送邀请？

**验证方法**：
1. 检查系统是否有二维码管理功能
2. 审核通过后检查是否自动发送邀请
3. 检查邀请通知是否包含二维码附件

---

### 评估维度 6：考核能力

**业务需求**（来自 send-exam-email.md 和 dev-guide/workflow.md）：

考核阶段：
- 进入条件：候选人加入实训群
- 系统行为：发送考核通知，提供众包任务和课堂资料链接
- 退出条件：候选人提交考核成果 → 进入评估；候选人退群 → 标记为退出

**评估问题**：
- [ ] 候选人入群后系统能否自动发送考核通知？
- [ ] 考核通知是否包含众包任务和课堂资料链接？
- [ ] 候选人能否在系统内提交考核成果？
- [ ] 候选人退群后系统能否自动标记退出？

**验证方法**：
1. 模拟候选人入群，检查是否收到考核通知
2. 检查考核通知内容是否完整
3. 检查考核成果提交流程
4. 检查退群状态同步机制

---

### 评估维度 7：流程自动化能力

**业务需求**（来自 survey.md 和 workflow.md）：

流程自动化目标：
- 候选人投递后，自动创建问卷任务
- 问卷任务关联候选人和问卷链接
- 候选人提交问卷后，系统自动更新状态
- 超时未提交，系统自动标记

**评估问题**：
- [ ] 状态能否自动流转？（投递→问卷→审核→邀请→考核→评估）
- [ ] 超时未提交系统能否自动标记？（问卷3天、邀请7天）
- [ ] 候选人退群系统能否自动标记退出？
- [ ] HR 能否看到状态流转历史？

**验证方法**：
1. 检查状态流转是否自动触发
2. 检查超时机制是否实现
3. 检查退群状态同步
4. 检查状态历史记录

---

### 评估维度 8：数据集中能力

**业务需求**（来自 survey.md）：

数据集中目标：
- 问卷链接存储到系统
- 候选人信息存储到系统
- 投递记录存储到系统
- 所有数据集中在一个地方

**评估问题**：
- [ ] 所有数据能否集中存储？（而非散落在邮件和飞书表格）
- [ ] HR 能否在系统内查看候选人完整信息？
- [ ] HR 能否导出候选人数据？
- [ ] 数据能否跨设备访问？

**验证方法**：
1. 检查数据存储方式（localStorage vs 数据库）
2. 检查候选人详情页是否完整
3. 检查数据导出功能
4. 检查数据访问方式

## 评估结果判定

### 业务目标达成标准

| 等级 | 标准 | 说明 |
|------|------|------|
| **完全达成** | 核心流程全部验证通过 | 可以完全替代邮件流程 |
| **基本达成** | 核心流程基本验证通过 | 可以部分替代邮件流程 |
| **部分达成** | 部分核心流程验证通过 | 需要补充功能才能替代 |
| **未达成** | 核心流程验证失败 | 无法替代邮件流程 |

### 核心流程验证标准

| 流程 | 验证标准 |
|------|----------|
| 投递 | 候选人能在系统内完成投递，系统自动发送问卷通知 |
| 问卷 | 候选人能在系统内看到问卷链接并填写，系统自动记录提交 |
| 审核 | HR 能在系统内看到问卷答案并审核，系统自动通知候选人 |
| 邀请 | 审核通过后系统自动发送邀请通知，包含群二维码 |
| 考核 | 入群后系统自动发送考核通知，候选人能提交成果 |
| 状态 | 状态自动流转，超时自动标记，退群自动标记 |
