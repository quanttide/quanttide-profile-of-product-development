# 量潮数据云用户故事地图

用户画像：需要为各产品提供数据处理与存储能力的数据工程师。

## 活动：数据契约

数据工程师先定义数据结构（字段、格式），作为后续处理、存储与计费的基准；各产品的数据按契约接入。

### 定义数据结构

- 数据工程师要先行定义数据契约（字段清单、格式），评估字段与信任字段同构（候选人档案契约先例）
- 数据工程师要能随产品迭代演进数据结构，保持向后兼容

### 数据接入

- 数据工程师要从来源平台/网站接入数据（采集、邮件拉取、历史数据迁移）
- 数据工程师要以量化进度同步采集状态（如"数据采集 32/543 组"）

## 活动：加工生成

数据工程师用 AI 按数据结构批量生成与加工数据，小批量、低成本地填满数据。

### AI 加工

- 数据工程师要用 AI 按数据结构批量生成内容（情绪日记加工、问卷分析等），小批量生成、假设不缓存
- 数据工程师要控制加工质量（质量不好可退款），让"效果付费"可兑现

### 数据清洗

- 数据工程师要清洗与结构化原始数据，产出可交付的数据集

## 活动：存储与生命周期

数据工程师按存储阶梯管理数据生命周期：保存期 → 只读 → 删除，数据随时可导出。

### 存储阶梯

- 数据工程师要按保存期 → 只读 → 删除的阶梯管理数据（对应热备 → 冷备 → 归档）
- 用户不续费时，数据工程师要按约定将数据转入只读并最终删除

### 开放导出

- 数据工程师要保证用户随时可导出自己的数据（格式开放、备份友好——数据是用户自己的）

## 活动：租户与安全

数据工程师按租户隔离数据，补齐安全短板：加密、隔离、审计。

### 租户隔离

- 数据工程师要按租户强制隔离数据（行级 tenant_id 过滤），确保不同团队互不可见
- 需为租户定制表时，数据工程师要用 schema 隔离；大客户托管时用库隔离

### 安全审计

- 数据工程师要加密敏感字段（按租户密钥）
- 数据工程师要记录数据的访问与变更审计信息

## 活动：计量与计费

数据工程师按处理与存储计量，支撑处理费 + 存储费的定价模型。

### 计量计费

- 数据工程师要按处理次数/存储量计量（处理费按次，如约 1 分/次；存储按年费）
- 数据工程师要支持资源包与会员额度，稳定收入预期

### 额度控制

- 不付费用户的数据要按阶梯进入只读与删除流程

## 活动：组件复用

数据工程师从后台云提取工具库与组件，供各前台复用。

### 工具库提取

- 数据工程师要从后台云提取工具库/组件，集成到各前台（课程云先例）
- 数据工程师要提供 API 供前台与服务端调用（Provider 模式）
