# 量潮数据云用户故事地图

用户画像：需要为各产品提供数据处理与存储能力的数据工程师。

## 活动：数据需求

数据工程师先明确数据需求：要什么数据、从哪来、量级与时间要求，作为后续规格与实现的输入。

### 需求收集

- 数据工程师要收集数据需求（数据来源平台/网站、已有数据形式、期望的数据集或代码）
- 数据工程师要明确数据量级与时间要求，评估工期与成本

### 需求确认

- 数据工程师要与需求方书面确认数据范围（交付范围、字段清单）
- 数据工程师要以量化进度同步状态（如"数据采集 32/543 组"）

## 活动：数据规格

数据工程师定义数据契约与蓝图：字段、格式、结构设计先行，作为实现与集成的基准。

### 数据契约

- 数据工程师要定义数据契约（字段清单、格式），评估字段与信任字段同构（候选人档案契约先例）
- 数据工程师要能随产品迭代演进数据结构，保持向后兼容

### 数据蓝图

- 数据工程师要设计数据蓝图（结构、关系、生命周期策略），先找到结构再填满数据
- 数据工程师要定义租户隔离方案（行级 tenant_id / schema 隔离 / 库隔离）

## 活动：实现

数据工程师按规格采集、加工、生成数据：接入数据源，用 AI 批量生成与清洗，产出可交付的数据集。

### 数据接入

- 数据工程师要从来源平台/网站接入数据（采集、邮件拉取、历史数据迁移）

### 加工生成

- 数据工程师要用 AI 按数据结构批量生成内容（情绪日记加工、问卷分析等），小批量生成、假设不缓存
- 数据工程师要清洗与结构化原始数据，产出可交付的数据集
- 数据工程师要控制加工质量（质量不好可退款），让"效果付费"可兑现

## 活动：运行

数据进入运行期：提供查询与 API 服务，按租户隔离运行，计量计费。

### 数据服务

- 数据工程师要提供 API 供前台与服务端调用（Provider 模式）
- 数据工程师要从后台云提取工具库/组件，集成到各前台（课程云先例）
- 数据工程师要按租户强制隔离数据（行级 tenant_id 过滤），确保互不可见

### 计量计费

- 数据工程师要按处理次数/存储量计量（处理费按次，如约 1 分/次；存储按年费）
- 数据工程师要支持资源包与会员额度，稳定收入预期

## 活动：传输

数据在端侧与服务端之间安全传输：导入导出、端侧接模型、传输安全。

### 导入导出

- 数据工程师要保证用户随时可导出自己的数据（格式开放、备份友好——数据是用户自己的）
- 数据工程师要支持端侧接入自有模型（处理放端侧或服务端的权衡）

### 传输安全

- 数据工程师要加密敏感字段（按租户密钥），保障传输与存储安全
- 数据工程师要记录数据的访问与变更审计信息

## 活动：备份和归档

数据按阶梯备份与归档：热备 → 冷备 → 归档，保存期 → 只读 → 删除。

### 备份归档

- 数据工程师要按热备 → 冷备 → 归档管理数据备份
- 数据工程师要按保存期 → 只读 → 删除的阶梯管理数据生命周期

### 删除与审计

- 用户不续费时，数据工程师要按约定将数据转入只读并最终删除
- 数据工程师要记录删除与访问的审计信息
