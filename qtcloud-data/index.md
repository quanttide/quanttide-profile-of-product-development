# 量潮数据云

## 定位：量潮云的数据后台，各产品数据处理与存储的底座

以产品形态提供数据处理与存储能力：数据契约、采集、加工、AI 生成、存储、导出与删除。与「量潮数据」（前台服务）成对——数据云承载其数据侧；同样承载健康、写作、机密等产品的数据需求。数据是用户自己的：格式开放、导出友好、备份容易。数据安全是必须补齐的短板，与机密云、安全云联动建设。

## 核心目标：让数据处理与存储有章法、可定价

定义数据结构 → AI 生成 → 存储与导出，全链路标准化；处理费 + 存储费，边界明确；不付费即删除，不背永久包袱；数据安全（租户隔离、加密、审计）与商业化同步设计，而不是事后补救。

## 阶段方法

- **数据契约先行**：数据结构（字段/格式）先行定义，评估字段与信任字段同构（候选人档案契约先例），避免事后集成
- **租户隔离阶梯**：行级隔离（PPG policy 强制租户过滤）→ schema 隔离（需为租户定制表时）→ 库隔离（大客户托管数据时）
- **存储阶梯**：保存期 → 只读 → 删除（对应热备 → 冷备 → 归档），与备份流程一致
- **组件提取复用**：从后台云提取工具库/组件集成到前台（课程云先例），提供 API 供前台与服务端调用

## 数据驱动

- 以数据为中心定价：处理费 + 存储费；处理按次/按量（如情绪日记约 1 分/次），存储收年费、不付费即删除
- 历史数据是冷启动资产：标注数据校准 AI（投递 → 筛选 → 结果 → 入职表现闭环）；小样本训练先找到数据结构，再填满数据
- 小批量生成、假设不缓存，生成成本可忽略；运营数据与产品日志驱动平台迭代

## 需求与 AI

- 定义数据结构 → AI 生成 → 人类验证（重验证、轻设计）；需求无歧义即正确——AI 觉得没有歧义就是对的
- 端侧可接自有模型与服务端提示词的权衡：从商业化考虑倾向服务端（好维护、好商业化），端侧自由选择是产品理念，两者需要权衡
- 明确性检验：能写出数据契约、做得出规格即明确，写不出来即模糊

## 商业化

处理费 + 存储费双轨：处理（AI 生成、加工）按次/按量收费，存储按年费、阶梯删除兜底（不付费即删）；精算与 SLA 按「卖保险」思路设计，溢价覆盖数据安全风险；资源包、会员固定化收入，稳定预期（应对按次计费收入可预期性差的难点）。
