# QtCloud Asset（量潮资产云）

## 定位

- 资产云的形态已大致清楚：前台（客户端层）实际上就是网盘，承载知识资产与各类文件的存取
- 高级功能体现在对资产格式规则的维护——命名规则、语义维护等，很多规则理论上可以硬编码
- 作为知识资产的契约（contract）中心：把第二大脑等资产的隐性结构显性化为契约，云端托管，团队通过 API 接入

## 核心目标

- 让资产可维护、可复用：从一个第二大脑中学习它的结构，复用到其他第二大脑上，把资产作为可维护、可复用的契约来维护
- 在真实资产的维护中发现规律，演化出资产运营的 MVP

## 阶段方法

- 按需创建：资产在创建时可能不是很全，不必一次性建全，按需创建——只要在规定的规则内部就是合理的，等需要处理时再进行必要的维护
- 云端维护：维护契约最好的办法是放在云端，团队层面通过 API 接入，为管理单位和契约单位将来具备管理基础提供可能
- 演化式探索：不需要提前设计结构，只告诉它明确的方向、目的与预期效果，给它自主空间去摸索演化
- 先从所有 GitHub 和对象存储维护起，从里面找规律，通过人机交互找到合适的结构

## 数据驱动

- 从所有 GitHub 与对象存储的真实资产中找规律，用维护过程中发现的结构反推规则设计
- 成本取决于 FaaS 提供服务的成本（单次成本），按边际价格计价（如一分钱一个月）；把应用数据与数据打通，能得到更准确的契约结果

## 需求与 AI

- 契约的边界即明确性：在契约内的按需创建是合理的，超出即需要重新定义契约
- 需求刻画只需明确方向、目的与预期效果，让系统自主摸索演化
- 当前系统缺少在极其有限的上下文中将其变得足够精密的技术，精密程度相比软件与业务所需的精密与准确程度还不够
