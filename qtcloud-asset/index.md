# QtCloud Asset（量潮资产云）

## 定位

资产云的契约（contract）中心：把第二大脑等知识资产的隐性结构显性化为 contract，云端托管，团队通过 API 接入。contract 是这个隐性知识的显性化，有了它就能得到比较准确的结果。

## 核心目标

从一个第二大脑中学习它的结构，复用到其他的第二大脑上——把资产作为可维护、可复用的契约来维护，这是工具的关键。

## 阶段方法

- **按需创建**：第二大脑在创建时可能不是很全，不想一次性把仓库都创建完，而是按需创建——只要在规定的 contract 内部就是合理的；等需要处理时再进行必要的维护处理
- **云端维护**：维护 contract 最好的办法是放在云端，团队层面通过 API 接入，这样就有明确有效的云端功能，也为管理单位和 contract 单位将来具备管理基础提供可能

## 数据驱动

成本取决于 FaaS 提供服务的成本（单次成本），按边际价格计价（如一分钱一个月）；如果把应用数据与数据打通，就能得到更准确的 contract 结果。

## 需求与 AI

contract 的边界即明确性：在 contract 内的按需创建是合理的，超出即需要重新定义契约。
