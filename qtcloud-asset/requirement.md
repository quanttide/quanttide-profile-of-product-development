# 量潮资产云用户故事地图

用户画像：需要托管与运营平台资产、维护资产格式规则的资产运营人员（管理员等内部角色）。

## 活动：资产托管

前台（客户端层）就是网盘，把 GitHub 与对象存储的资产都维护起来。

### 任务：网盘存取

· 用户要以网盘形式统一存取各类资产（前台即网盘）
· 用户要把 GitHub 与对象存储的资产都纳入维护范围

### 任务：按需纳入

· 用户要按需纳入资产，不必一次性建全
· 用户要在需要处理时再进行必要的维护

## 活动：规则维护

高级功能体现在对资产格式规则的维护，很多规则理论上可以硬编码。

### 任务：命名规则

· 用户要维护资产的命名规则，让资产命名有章可循
· 用户要把可以硬编码的规则固化下来

### 任务：语义维护

· 用户要维护资产的语义，保持资产含义清晰、可被准确理解

## 活动：演化式探索

不需要提前设计结构，只告诉它明确的方向、目的与预期效果，让它摸索演化。

### 任务：找规律

· 用户要在 GitHub 与对象存储资产的维护过程中发现规律
· 用户要通过人机交互找到合适的资产结构

### 任务：形成运营 MVP

· 用户要在演化中找到资产运营的 MVP
· 用户要在明确方向、目的与预期效果的前提下获得自主探索空间

## 活动：云端接入

契约放在云端，团队层面通过 API 接入。

### 任务：云端托管

· 用户要把资产契约托管在云端，团队通过 API 接入
· 用户要管理契约的访问（管理单位、契约单位具备管理基础）

### 任务：计量定价

· 用户要按 FaaS 服务的单次成本看到边际价格（如一分钱一个月）
· 用户要能用契约费用计算基础设施成本
