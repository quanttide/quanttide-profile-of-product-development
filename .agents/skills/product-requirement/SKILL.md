# 用户故事地图撰写技能

## 目标

撰写一份可信赖的产品用户故事地图：以用户视角刻画产品需求，让所有人看到同一张产品地图。

## 流程

### 第一步：确定用户画像

一行完成：`用户画像：需要…的[角色]`

### 第二步：划分活动（用户旅程阶段）

按用户行为的时间顺序划分活动（不是系统模块）。

每个活动包含：
- **活动名**：`## 活动：[阶段名]`
- **活动描述**：一段话说明这个阶段的流程、目标、价值
- **任务列表**：活动内的具体动作

### 第三步：梳理任务和故事

任务 = `### 任务：[动词+名词]`

故事 = 每条以"用户要…"开头：

```
· 用户要[动作]，[目的/价值]
```

### 第四步：评审校验

逐条检查（见验收标准），修正不合格的故事。

## 验收标准

### 必须满足

- [ ] 每个活动都有描述段（一段话说明流程/目标/价值）
- [ ] 所有故事都是"用户要…"句式（无系统动作混入）
- [ ] 活动按用户旅程时间顺序排列（不是系统架构顺序）

### 质量检查

- [ ] 故事颗粒度一致（不过大、不过细）
- [ ] 没有功能清单式描述（"支持XX"不是故事）
- [ ] 用户画像一行完成（角色 + 需求）

### 反模式（避免）

| 问题 | 示例 | 修正 |
|------|------|------|
| 系统动作 | "系统要记录部署状态" | "用户要记录部署状态…" |
| 功能清单 | "支持多租户" | "用户要按租户隔离数据…" |
| 模块当活动 | "活动：认证模块" | "活动：用户登录" |
| 缺描述段 | 直接列任务 | 先写活动流程说明 |
