# 用户故事地图 · 量潮云 (QtCloud)

> 按用户故事地图的三层结构组织：活动（用户旅程的宏观阶段）→ 任务（活动内的具体动作）→ 故事（具体功能点）。优先级即版本规划：P0 当前版本必备，P1 重要，P2 增强，待研究为未决方法。

## 活动一：日常使用

### 任务：工作台

- 作为日常工作平台，逐步替代 WorkBuddy、Zed 等高频入口。P0

### 任务：端侧工具

- 工具台、工作台、命令行提供基本功能，免费使用、可接自有模型。P1
- 服务端提供提示词与处理能力，支持商业化。P1

## 活动二：产品承载

### 任务：实验室

- 以实验室承载原型（替代 PRD），静态 HTML 可直接上线，可加后端变动态应用。P1

### 任务：产品全景

- 以用户故事地图公开所有产品的路线与理解方式，作为静态网站上线。P1

## 活动三：商业化

### 任务：付费机制

- 基础功能免费，按处理/存储收费，定价以数据为中心。P1
- 销售资源包、会员，稳定收入预期。P2

### 任务：增长漏斗

- 免费端侧吸引用户规模，小额基础服务激活付费。P1
- 公司代金券作为 package 的一部分提供给员工。P2

## 活动四：数据治理

### 任务：存储阶梯

- 数据保存期 → 只读 → 删除 的阶梯流程。P1

### 任务：数据安全

- 数据安全与审计机制（与机密云、安全云协同）。P1

## 活动五：媒体运营

### 任务：官网动态

- 官网「动态」板块发布公告、技术博客，作为公众号、知乎等平台的事实源。待研究
- 后台沉淀为新媒体云。待研究
