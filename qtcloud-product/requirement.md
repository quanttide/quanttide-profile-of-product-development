# 需求清单 · 量潮产品云 (QtCloud Product)

## 一、产品体系

产品体系的构建是产品的核心目标：用一个元结构管理产品的结构，跨系统边界时优先关注产品之间的关系。

- 作为产品负责人，我希望登记每个产品（名称、状态、负责人），以便形成完整的产品清单。P0
- 作为产品负责人，我希望在多个产品间切换（每个产品 = 一个项目空间），以便集中管理所有产品。P0
- 作为产品负责人，我希望查看跨产品的组合视图（成熟度、投入分布、版本时间线），以便做产品取舍与资源分配。P1
- 作为产品负责人，我希望管理产品之间的关系（跨系统边界的关系优先于产品内部知识），以便支撑产品体系的整体决策。P1

## 二、需求刻画：用户故事地图

需求刻画采用用户故事地图，已成体系。

- 作为产品经理，我希望在一块画布上看到用户故事地图的三层结构（活动层 / 任务层 / 故事卡），以便所有人看到同一张产品地图。P0
- 作为产品经理，我希望活动跨列合并显示（如一个活动横跨多个任务列），以便表达活动的真实跨度。P0
- 作为产品经理，我希望故事按 Release 版本行组织且行可折叠，以便聚焦某个发布版本的范围。P0
- 作为产品经理，我希望横向、纵向双轴滚动浏览整张地图，以便在大量故事中定位。P0
- 作为产品经理，我希望长按拖拽故事卡片、在任务列间重新组织，以便调整地图结构。P0
- 作为产品经理，我希望拖动 MVP 发布线（水平红线），以便标记当前版本与未来迭代的边界。P1

## 三、规格描述：事件风暴

规格描述采用事件风暴，已成体系（规划中）。

- 作为架构师，我希望以事件风暴梳理产品规格（领域事件、业务规则），以便准确描述产品行为。P1

## 四、QA 验收

QA 验收目前只有用例，缺少更敏捷的成体系方法，待研究。

- 作为 QA，我希望管理验收用例，以便验证产品是否满足需求。P2
- 作为产品团队，我希望找到比用例更敏捷的成体系验收方法，以便跟上敏捷节奏。待研究

## 五、运营与数据

最后阶段是运营而非复盘：收集所有实际运营数据（含各类观测数据），数据驱动找到合适的产品结构。

- 作为产品运营，我希望收集实际运营数据（包括各类观测数据），以便持续检验产品。P1
- 作为产品团队，我希望通过不断填入有用数据来发现合适的产品管理结构，以便产品体系在真实使用中自然生长。P1
