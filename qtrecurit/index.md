# 量潮招聘

## 定位：候选人的透明窗口与信任场

招聘系统，产品阶段：筛选标准化、信任承载平台、品牌商业化、信用系统的市场价值。课堂是导流入口（流量场），招聘承载主体功能（信任场），信任优先。与人事云的边界：人事云提供 HR 通用能力，量潮背书与推荐决策是 qtrecurit 商业数据，与之隔离。

## 核心目标：让候选人用同一套标准、同一套数据看自己

公平不是口号，是可公开、可验证的机制——考评标准公开、过程可查、结果可见。候选人凭真本事积累信用，携带背书投递其他企业。

## 阶段方法

筛选标准化与信任承载并行（共享候选人档案契约，评估字段与信任字段同构），再整合为统一候选人档案，最后商业化与信用系统。CLI 采集 → Provider 存储聚合 → Studio 候选人透明窗口、Site 对外招聘门户。对 CLI 工具的新认识：它可用来处理大批量发邮件所遇到的困难，验证场景非常真实——大批量发邮件且不能发错；CLI 承担零容错的批量操作，与采集能力共同构成命令行工具的价值。

## 数据驱动

信任数据只能在筛选过程中积累；历史招聘数据是平台冷启动资产（AI 初筛校准集、初始信用档案、标准模板库）；信用复利：被推荐者入职表现反哺推荐信可信度。

## 需求与 AI

AI 参与边界决策（课堂导流、主体功能在招聘）；AI 初筛与匹配度排序，HR 人工复核。明确性检验：能做出规格、写得出用户故事即明确。

## 商业化

企业是资源（免费）、候选人是资产（信用凭证）、收入来自候选人端（课堂学费 + 推荐服务费）、竞争点是信用。推荐是服务不是卖信用；付费与推荐结果隔离（推荐信凭证据出具）；按交付收费不按结果收费。推荐信是第一个实体交付物；人事云升级多租户平台，qtrecurit 为样板租户。
