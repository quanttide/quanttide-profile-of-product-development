# 量潮招聘（qtrecurit）

## 定位：候选人的透明窗口与信任场

招聘系统，路线图承接四个产品阶段：筛选标准化、信任承载平台、品牌商业化、信用系统的市场价值。与课堂（qtclass）联动：课堂是导流入口（流量场），招聘平台承载主体功能（信任场），取舍原则**信任优先**。与人事云（qtcloud-human）的边界：人事云提供 HR 领域通用能力（档案、筛选、评估、推荐信模块）；量潮背书状态与推荐决策是 qtrecurit 的**商业数据**，与人事云客户数据隔离。

## 核心目标：让候选人用同一套标准、同一套数据看自己

公平不是口号，是可公开、可验证的机制：**考评标准公开、考评过程可查、考评结果可见**。Studio 是候选人的透明窗口，不做内部管理台（内部操作由 CLI 与 Provider 承担）。招聘不仅自招，也帮其他企业推荐——企业是资源方（永远免费），候选人凭真本事获得可携带的信用凭证。

## 阶段方法

- **v0.1**：阶段一（筛选标准化）与阶段二（信任承载平台）**并行**——共享候选人档案契约（评估字段 + 信任字段同构），筛选评估的产出即信任档案的记录，从第一天避免事后集成
- **v0.2**：整合为**统一候选人档案**（标准 + 过程 + 结果 + 信任），数据闭环（筛选产生信任，信任反哺筛选），PDF 导出
- **v0.3+**：商业化与信用系统——多租户平台、推荐服务产品化、课堂导流
- **两端分工**：CLI（Rust）采集行为记录 → Provider（Go）存储聚合 → Studio（Flutter）候选人透明窗口；Site（React）对外招聘门户（招聘启事 + 招聘数据公开）

## 数据驱动

- **信任数据只能在筛选过程中积累**：历史行为记录是筛选、实训、合作过程的副产品；先做筛选再做信任会死锁，故并行
- **历史招聘数据是平台冷启动资产**：AI 初筛校准集（投递 → 筛选 → 结果 → 入职表现的标注闭环）、初始信用档案、筛选标准模板库
- **数据飞轮**：筛选产生信任数据，信任记录（实训表现）反过来校准筛选标准；被推荐者入职表现（绩效记录）反哺推荐信可信度，构成信用复利

## 需求与 AI

- AI 参与产品边界决策（3 个 AI 对课堂/招聘边界建议一致：课堂导流、主体功能在招聘）
- AI 初筛（以历史标注数据校准）与匹配度排序，企业 HR 人工复核；筛选评估的产出格式即信任档案的记录格式（契约先行）
- 明确性检验：能做出规格、写得出用户故事即明确，写不出来即模糊

## 商业化

与一般招聘平台**完全相反**：企业是资源（免费获得被验证人才）、候选人是资产（信用凭证）、收入只来自候选人端（课堂学费 + 推荐服务费）、竞争点是信用（可公开、可验证）而非流量。三个核心决策：

1. **推荐是服务，不是卖信用**：收服务费、交付服务（匹配、内推、推荐信、过程反馈），不交付结果担保
2. **付费与推荐结果隔离**：钱买的是"成为可被推荐的人的过程"（课堂学习、实训、开源参与）；推荐信是凭证据出具的质检报告，付费买不到证据，证据只能靠干活挣
3. **按交付收费，不按结果收费**：结果担保是招聘服务被整治的重灾区（付费内推、保 offer、培训贷），守红线即守信用资产

**推荐信是商业化的第一个实体交付物**，其可信度决定整个商业模式的成败：CLI 采集 → Provider 聚合 → Studio 按凭证生成，付费链路与证据链路在数据层不交叉。

**多租户平台**：人事云升级为多租户后端，qtrecurit 作为样板租户（dogfooding）；企业客户拥有品牌化招聘前台（`{tenant}.jobs.quanttide.com`），使用量潮 AI 初筛与信用背书服务。
