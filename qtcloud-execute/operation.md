# 量潮执行云运营机制：CEO 办公室任务机制 v0.1

> 落地载体：执行云（execute.cloud.quanttide.com）。目的：解决「传话失真 / 优先级混乱 / 任务静默卡住 / 老板靠催才知道进度」的管理问题。

## 问题

- **任务生命周期没有被承载**：老板发消息 → 大家收到 → 开始执行 → 过程消失 → 到时间才发现没完成。邮件管通知、聊天管沟通，但没人管「事情现在到哪了」
- **传话失真**：信息每多中转一层就失真一分，中转层在「理解→转述」时容易加工降级（把「紧急联系」听成「备一个方案」），错误在中转时发生且不可见
- **靠人催**：老板必须亲自问才能知道进度，等于老板替系统承担了「追踪」职能

## 核心思路：让执行透明，老板只做校对

| 层级 | 机制 | 作用 |
|------|------|------|
| ① 源头 | 任务都是老板想的，我们只负责「翻译 + 发布」 | 明确职责边界 |
| ② 校正点 | 发布任务卡时，卡片贴回群里让老板扫一眼纠错 | 理解错了当场改，错不落地 |
| ③ 透明 | 过程留痕，老板随时可查 | 不用汇报，不占老板时间 |
| ④ 减决策 | 正常静默，异常才报 | 老板只在值得介入的节点出现 |

一句话：不是让老板少知道，而是让他「低成本地知道 + 只在必要时才被叫到」。类比外卖订单：下单后不用盯着骑手，但打开 App 随时能看进度，只有超时才推送提醒。

## 任务卡

字段（第一版，够用即可）：任务名称 / 任务编号（CEO-YYYYMMDD-NNN）/ 优先级（P0 紧急·外部·阻塞他人 / P1 / P2）/ Owner（唯一负责人）/ 协作人 / 来源（CEO 办公室）/ 截止时间（硬截止）/ 当前状态（🟢 未开始 / 🟡 进行中 / 🟠 有风险 / 🔴 卡住 / ⚪ 已完成）/ 下一步动作（下一件具体要发生的事 + 负责人 + 预计完成时间）/ 卡点（现在有什么东西阻止它往前）/ 节点（时间节点表）

## 节点三步拆法

1. **先定终点**：这个任务做完长什么样？
2. **找「必须停下来看一眼」的环节**：等别人（外部依赖）、交接到别人手上、有硬截止、容易出错要检查
3. **切开，标时间 + 产出 + 负责人**，3~5 个节点，宁少而准

规则：节点设在哪不看均匀，看「哪里可能卡住」；时间预估保守，宁松勿紧——太紧天天变红，红黄绿失效（狼来了）。

## 分工

- **老板**：校对卡片 + 只看异常
- **CEO 办公室（发布者）**：发布、**问**节点、校验三件套（截止时间 / Owner / 下一步）、追红灯；不需要懂业务，价值是「会问、会记、会校对」，业务节点用三个问题问出来：① 这活做到哪一步算「有实质进展」？② 中间要等谁、哪里容易卡？③ 预计什么时候完成？执行人口述，发布者代笔
- **执行人（Owner）**：设自己的业务节点 + 点亮状态

**保证更新**：节点到点没人点亮 → 自动转黄 → 再拖转红。「更新」不靠执行人自觉，靠「不点亮就亮灯」——系统替你和老板盯着。

## 升级路径：个人看板 → 组织执行系统

现有执行云（看清 / 推进 / 提炼）全部保留——本质是**个人任务看板**，解决「人忘记任务」：任务都是自己的，没有负责人、没有老板/组织视角。

CEO 机制补的：**Owner、Next Action、Blocker** 三件套，加红黄绿状态与节点报警。任务不止「待办→进行中→完成」，而是：

**任务产生 → 明确责任 → 开始执行 → 持续推进 → 异常暴露 → 协调解决 → 完成闭环**

管理视图：今日任务 N；🔴 阻塞 / 🟡 风险 / 🟢 正常 / ⚪ 完成。老板第一眼只看红色，再看「需要我决策」「需要我协调」两项。

一句话：现有执行云「靠人记得 → 靠系统看清」；CEO 机制「靠人催 → 靠系统推进」。
