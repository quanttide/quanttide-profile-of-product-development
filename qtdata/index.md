# 量潮数据

## 定位：以项目制交付的数据处理服务

承接客户的数据需求（数据采集、加工、结构化），交付数据集与代码（含字段清单）。与「数据云」成对：量潮数据是前台服务形态，数据云承载存储与处理；与课程研发并列为量潮的主要商业产品之一。

## 核心目标：让客户以可预期的成本获得想要的数据

从承接（数据现状、期望结果、数据量级与时间要求）到交付（数据集/代码），每步关键节点以邮件书面确认——既是对客户的正式承诺，也是内部留痕与审计依据。形成可复制的服务：按难度/数据量级/工时公式化报价，交付物与字段清单可验收。

## 阶段方法

商务流程七阶段：订单承接 → 方案报价 → 合同启动 → 执行监控 → 验收交付 → 尾款发票 → 收尾留存。角色分工：商务主导商务链路（承接/报价/合同/发票/尾款），PM 负责进度汇报、风险同步、验收交付，销售只参与成交前，财务配合开票。关键规则：书面确认优先（范围、价格、工期、验收一律邮件留痕）；变更走书面评估（范围/工期/费用影响后补签协议）；48 小时未回复跟进、付款 7 天未到账催收；全部往来邮件按项目归档。

## 数据驱动

历史项目沉淀（采集方法、数据格式、字段结构）复用为标准化服务与数据报告；执行过程以量化进度同步（如"数据采集 32/543 组"），让状态可观测。数据安全（存储与审计）是短板，与数据云的存储阶梯（保存期 → 只读 → 删除）与开放导出机制同步设计。

## 需求与 AI

需求在承接阶段收集（来源平台/已有数据形式、期望数据集或代码、量级与时间），策划书确认交付范围与时间规划，变更以书面确认为准——能写清交付范围（数据集/代码 + 字段清单）即明确。AI 用于数据采集与加工（定义数据结构 → 生成 → 交付），小批量生成成本可忽略。

## 商业化

公式化报价（难度/数据量级/工时）+ 毛利底线，降价走降本方案重报；付款节点首款/中期/尾款，尾款结清后交付全部成果；以数据为中心定价（处理费 + 存储费，数据云承载）。收尾留存转介绍与长期合作（学术圈推荐、数据报告、数据云、课程培训）。
